# Plasmic pages in Ember

The Kaizen Plasmic project (`4WZ4je7EqYHVjfVVU6jztT`) supplies the visual page layers. Run `npx plasmic sync --projects 4WZ4je7EqYHVjfVVU6jztT --yes --skip-upgrade-check` after editing in Studio, then build and commit the generated files. The GitHub workflow `.github/workflows/plasmic-sync.yml` can do this on dispatch when `PLASMIC_AUTH_JSON` is configured in the repository.

| App route | Editable Plasmic page | Runtime behavior |
| --- | --- | --- |
| `/` | Home Editable | Links into authentication |
| `/auth` | Login Editable / Sign Up Editable | Supabase sign-in and sign-up in `src/routes/auth.tsx` |
| `/dashboard` | Dashboard Native | Profile, missions, rewards and creation in `DashboardPanel` |
| `/tasks` | Missions Editable | Live task management in `src/routes/_authenticated/tasks.tsx` |
| `/character` | Character Editable | Live profile and attributes in `src/routes/_authenticated/character.tsx` |

The authenticated Plasmic pages provide the editable header, navigation, main container and footer. Their sample content inside `main` is replaced by live React content through named node overrides in `src/components/plasmic-app-page.tsx`; changing that sample content in Studio will not affect the live data area. Auth forms remain native Plasmic layers, with submission attached in the route wrapper. The `/plasmic-home` page remains a legacy code-component preview. The other `*-editable` URLs are visual previews and contain sample data.

Do not edit files under `src/components/plasmic-linked/kaizen` directly. They are regenerated by Plasmic. Keep application actions and data wiring in the route wrappers and regular components.
